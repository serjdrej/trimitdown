# trimitdown-pdf

*Read in English: [README.md](https://github.com/serjdrej/trimitdown/blob/main/packages/trimitdown-pdf/README.md)*

**Стадия проверки, которой у pdfplumber нет.**

`page.find_tables()` отвечает на вопрос *«где размеченные линиями ячейки?»* — и
никогда не отвечает на вопрос *«а это вообще таблица?»*. Любая рамка страницы,
пересечённая линейкой, возвращается как сетка, и конвейер рендерит фирменный
бланк двенадцатиколоночной таблицей.

Этот пакет — недостающий предикат. Это не «ещё один конвертер PDF».

```bash
pip install trimitdown-pdf
```

## Встроить в существующий конвейер на pdfplumber

Если конвейер уже есть — нужна именно эта часть. Извлекайте строки ровно как
сейчас, а перед тем как оставить сетку, спросите, настоящая ли она:

```python
import pdfplumber
from trimitdown_pdf import is_real_table, TABLE_SETTINGS, TEXT_SETTINGS

with pdfplumber.open("report.pdf") as pdf:
    for page in pdf.pages:
        for table in page.find_tables(TABLE_SETTINGS):
            rows = [
                [(cell or "").replace("\n", " ").strip() for cell in row]
                for row in table.extract(**TEXT_SETTINGS)
            ]
            rows = [r for r in rows if any(r)]

            if not is_real_table(rows):
                continue  # рамка страницы или блок вёрстки — пропускаем

            handle(rows)  # ваш существующий код
```

`TABLE_SETTINGS` и `TEXT_SETTINGS` поставляются вместе с предикатом, потому что
`is_real_table` осмыслен только на строках, извлечённых так же, как при его
калибровке. `TEXT_SETTINGS` особенно важны: когда задан `x_tolerance_ratio`,
pdfplumber полностью игнорирует `x_tolerance`, поэтому любое место вызова, где
их забыли, молча откатывается к дефолту в 3 pt и снова склеивает слова.

### Что делает предикат

Критерий обнаружения Нурминена (из `NurminenDetectionAlgorithm` в tabula-java),
применённый к ячейкам pdfplumber: таблице нужно не меньше двух строк, в которых
заполнены хотя бы две колонки, и такие строки должны составлять большинство
среди всех непустых.

Замерено на размеченном вручную наборе из 74 сеток: сохраняется 44 из 45
настоящих таблиц, отбрасывается 13 из 14 рамок вёрстки. Геометрические признаки
(длина ячейки, покрытие, доля пустых) были опробованы и отвергнуты — они
уничтожают 29–49% настоящих таблиц.

## Или взять рендерер целиком

Если конвейера нет и нужен просто markdown на выходе, `pdf_to_markdown`
оборачивает то же обнаружение фильтрацией мусора от диаграмм, обработкой
вложенных рамок и чередованием прозы и таблиц в порядке документа:

```python
from trimitdown_pdf import pdf_to_markdown

print(pdf_to_markdown("report.pdf"))
```

## Замер против markitdown

`scripts/measure_corpus.py` в репозитории прогнал оба движка по двум независимым
коллекциям — 891 реальный PDF, около 600 МБ — на одной машине и на одной версии
pdfplumber (2026-07-24). Шесть из них сломаны в источнике: в них почти не
закодированы пробелы между словами, и они вынесены отдельно в
[`docs/pdf-engine.md`](https://github.com/serjdrej/trimitdown/blob/main/docs/pdf-engine.md),
чтобы горстка патологических файлов не тянула на себе результат. Заголовочные
числа — по остальным 885, из которых 226 без единой размеченной линиями сетки:

| | markitdown | trimitdown-pdf |
| --- | --- | --- |
| строк таблиц на документах без сетки | 5624 | **2** |
| склеенных словоформ | 107 | **53** |
| документов со склейкой | 24 (3%) | **18 (2%)** |
| цифр выдумано против текста страницы | 0 | 0 |
| цифр потеряно против текста страницы | 0 | 0 |
| сбоев конвертации | 0 | 0 |
| токенов на выходе | 5 528 360 | **5 011 180** (−9,4%) |

Результат по выдуманным таблицам — тот, который держится: он воспроизводится на
каждой коллекции по отдельности (1497→2 и 4127→0), ни на одном документе движок
не проигрывает markitdown, и меньший счёт токенов — это в основном те самые
невыдуманные строки.

**Токенов меньше, и не за счёт выброшенного содержимого.** Оба движка сверялись
с собственным `extract_text()` каждой страницы: ни один не выдумал ни одной
цифры и ни одной не потерял — на всех 885 документах. Проверка охватывает только
цифры и не доказывает полноту по словам, но она закрывает тот способ провала,
при котором конвертер выглядит экономным, потому что молча выбрасывает то, с чем
не справился.

Там, где движок **стоит** токенов, он об этом говорит. На 309 из 885 документов
вывод больше — медиана перерасхода 32 токена, свыше 1000 выходят восемнадцать.
Это документы, плотно набитые таблицами, а перерасход — синтаксис markdown-
таблиц: палки и строка-разделитель суть цена сохранения структуры, которую
плоский текст теряет.

Склейка — выигрыш скромнее. На 870 из 885 документов движки идут вничью, на 11
этот движок лучше, а на четырёх **проигрывает**, худший случай — на 17 склеек,
на формах, где отступы закодированы настоящими пробелами. Это
задокументированный дефект, а не артефакт округления.

Корпус — сторонний материал под копирайтом, он не публикуется. Скрипт замера —
публикуется: наведите его на свои PDF, и он напечатает такую же таблицу.

## Ограничения — прочитайте сначала их

- **Только размеченные линиями сетки.** Движок работает с
  `vertical_strategy: "lines"`. Безбордюрные и выровненные пробелами таблицы не
  обнаруживаются **вообще** — не плохо, а никак. Если ваши документы
  безбордюрные, этот пакет для вас не делает ничего.
- **Никакого OCR.** Сканы и PDF из одних картинок не дают текста, запасного пути
  нет. Но вместо пустоты страница без текстового слоя выводится одной строкой,
  которая называет саму себя:

  ```
  [trimitdown-pdf: no extractable text layer on page 12]
  ```

  Она не добавляет информации, которой на странице не было: стоит порядка 55
  символов на страницу и OCR не заменяет. Её единственная задача — сделать
  пропуск находимым обычным поиском, чтобы конвейер отправил такие страницы в
  OCR, а не проиндексировал дыру, которой не заметил. Подстрока
  `no extractable text layer` стабильна, на неё можно опираться. В замеренном
  корпусе таких страниц было 581.
- **Никакой модели вёрстки.** Многоколоночный поток страницы, порядок чтения
  между колонками, колонтитулы и подписи к рисункам — вне области.

Если нужны безбордюрные таблицы, OCR или полная вёрстка документа — берите
[marker](https://github.com/datalab-to/marker) или
[Docling](https://github.com/docling-project/docling). Этот пакет решает одну
узкую задачу, которую те инструменты не отдают наружу переиспользуемым
предикатом.

## Стабильность

**API нестабилен до 1.0.** `0.x` означает, что имена и сигнатуры могут
измениться в любом релизе. Если вы на него завязались — пиньте точную версию.

## API

| Имя | Назначение |
| --- | --- |
| `is_real_table(rows) -> bool` | Предикат обнаружения. |
| `pdf_to_markdown(path) -> str` | Рендерер целого документа, для удобства. |
| `TABLE_SETTINGS` | Настройки `find_tables()`, которые предполагает предикат. |
| `TEXT_SETTINGS` | Настройки `extract()`, которые предполагает предикат. |
| `X_TOLERANCE_RATIO` | Коэффициент допуска, стоящий за `TEXT_SETTINGS`. |
