# Релиз

Порядок ручной и намеренно ручной: каждый шаг ниже необратим по-своему, а автоматический
триггер срабатывает и тогда, когда не собирался.

## 1. Предрелизный гейт на корпусе

CI его прогнать не может — корпуса у него нет:

```bash
export TRIMITDOWN_CORPUS=/путь/к/корпусу
pytest -m corpus
```

Зелёный CI сам по себе не означает, что детекция таблиц не поехала. Подробности — в
[DEVELOPMENT.md](DEVELOPMENT.md).

## 2. Поднять номер версии

Единственный источник — `__version__` в `src/trimitdown/__init__.py`. Больше нигде номер не
пишется; `tests/test_packaging.py` следит за этим и падает при появлении второго литерала.
Коммит с подъёмом версии уходит в `main` до релиза.

## 3. Собрать релиз

Actions → **Release** → Run workflow, поле `version` — номер без ведущей `v` (например `1.2.3`).
Workflow сверит номер с пакетом, прогонит переносимый набор тестов, соберёт три бандла, проверит
комплектность, посчитает SHA256 и создаст **черновик** релиза.

С ветки конвейер доходит до контрольных сумм и останавливается, не создавая релиза, — так его
можно проверить целиком, ничего не публикуя.

## 4. Опубликовать черновик

Releases → черновик → проверить вложения и заметки → Publish. Тег `v<версия>` создаётся **в этот
момент**, не раньше. Заголовок релиза — только номер версии. Заметки двуязычные.

## 5. Опубликовать пакеты на PyPI

Actions → **Publish to PyPI** → Run workflow, выбрать проект: `trimitdown` (приложение) или
`trimitdown-pdf` (движок). Публикация проходит через Trusted Publishing (OIDC), токенов в
репозитории нет и не должно появиться. Между сборкой и загрузкой стоит ручное подтверждение
окружения `pypi`.

**Номер версии на PyPI сгорает необратимо.** Загруженную версию нельзя ни заменить, ни
переиспользовать после удаления. Ошибка в номере чинится только следующим номером.

Новый проект на PyPI требует, чтобы владелец заранее завёл для него Trusted Publisher (pending
publisher): репозиторий `serjdrej/trimitdown`, workflow `publish-pypi.yml`, окружение `pypi`.

## 6. Перенаправить манифест scoop

```bash
python scripts/update_scoop_manifest.py 1.2.3
```

Переписывает версию, ссылку и хеш в `bucket/trimitdown.json` — все три обязаны
меняться вместе, а поправленные вручную два из трёх дают несовпадение хеша у
каждого пользователя сразу. Хеш берётся из `SHA256SUMS`, приложенных к релизу:
это контрольные суммы тех байт, которые опубликованы, а не результат повторной
загрузки.

**Скрипт отказывается работать с черновиком.** Манифест, указывающий на
черновик, отправляет всех пользователей scoop на несуществующий URL и при этом
выглядит в ревью правильным. Поэтому шаг идёт после публикации, а не до.

Коммит с обновлённым манифестом — обычный, в `main`. Бакет — сам этот
репозиторий, отдельного не нужно.

## Чего конвейер не делает

- Не создаёт тег до публикации черновика.
- Не публикует релиз сам — только черновик.
- Не собирает релиз с ветки.
- Не публикует на PyPI по тегу или по релизу: только руками, только с подтверждением.
